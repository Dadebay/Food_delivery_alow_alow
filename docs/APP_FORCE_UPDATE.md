# Принудительное обновление приложения (force update)

Документ для backend- и admin-команды AlowAlow. Описывает, что нужно
реализовать на сервере и в админке, чтобы приложение могло блокировать
устаревшие сборки после релиза в Google Play и App Store.

Мобильная часть **уже реализована** и ждёт endpoint.

```text
App start -> GET /app/version?platform=IOS|ANDROID
          -> сравнение версий на клиенте
          -> minSupportedVersion > текущей  => экран-блокировка
          -> latestVersion      > текущей  => мягкое предложение обновиться
          -> иначе                          => обычный запуск
```

## Зачем нужно

После публикации новой версии часть пользователей остаётся на старой сборке
неделями. Если старый клиент ломает контракт API (изменилось поле, удалён
endpoint, изменилась логика цен), он начинает работать неправильно, а
пользователь видит не ошибку обновления, а «приложение сломалось».

Force update даёт возможность закрыть такие сборки одной записью в админке,
без нового релиза мобильного приложения.

## Endpoint, который нужно реализовать

```http
GET /api/v1/app/version?platform=ANDROID
```

`platform` — строго `ANDROID` или `IOS`. Приложение всегда передаёт параметр.

Авторизация **не требуется**: проверка выполняется до входа пользователя, на
самом первом экране. Endpoint должен быть публичным.

### Ответ

```json
{
  "latestVersion": "1.4.0",
  "minSupportedVersion": "1.2.0",
  "storeUrl": "https://play.google.com/store/apps/details?id=com.gurbanov.alowalow",
  "releaseNotesRu": "Добавили оплату картой и ускорили карту.",
  "releaseNotesTk": "Kart bilen töleg goşuldy we karta çaltlaşdyryldy."
}
```

| Поле                 | Тип           | Обязательное | Назначение                                                   |
| -------------------- | ------------- | ------------ | ------------------------------------------------------------ |
| `latestVersion`      | string        | да           | Последняя опубликованная в сторе версия                      |
| `minSupportedVersion`| string        | да           | Минимальная версия, которая ещё допускается к работе         |
| `storeUrl`           | string        | да           | Ссылка на страницу приложения в сторе этой платформы         |
| `releaseNotesRu`     | string / null | нет          | Текст «что нового» на русском                                |
| `releaseNotesTk`     | string / null | нет          | Текст «что нового» на туркменском                            |

### Формат версии

Только маркетинговая версия в виде `MAJOR.MINOR.PATCH` — `1.4.0`.

Не отправляйте build number (`1.4.0+37`). Пользователь в сторе видит именно
маркетинговую версию, и админ вводит её же. Клиент сравнивает числа по
компонентам, поэтому `1.10.0` корректно считается новее, чем `1.9.3` —
строковое сравнение дало бы обратный результат.

### Ссылки на сторы

- Android: `https://play.google.com/store/apps/details?id=com.gurbanov.alowalow`
- iOS: `https://apps.apple.com/app/id<APP_STORE_ID>`

`<APP_STORE_ID>` — числовой идентификатор, который Apple выдаёт после первой
отправки приложения в App Store Connect. До первой публикации его не
существует.

**Поэтому `storeUrl` приходит с сервера, а не зашит в приложение.** Если
ссылка окажется неверной, заблокированный пользователь не сможет установить
обновление — а новую сборку он установить тоже не может, потому что она
блокируется. Ссылку нужно иметь возможность исправить без релиза.

## Что должно быть в админке

Раздел «Настройки → Версии приложения». Отдельная запись на каждую платформу.

### Поля формы

| Поле                       | Контрол            | Валидация                                   |
| -------------------------- | ------------------ | ------------------------------------------- |
| Платформа                  | ANDROID / IOS      | обязательное, уникальное                    |
| Последняя версия           | текст              | `^\d+\.\d+\.\d+$`                           |
| Минимальная версия         | текст              | `^\d+\.\d+\.\d+$`, **не выше** последней    |
| Ссылка на стор             | текст              | валидный `https://` URL                     |
| Что нового (RU)            | textarea           | необязательное                              |
| Что нового (TK)            | textarea           | необязательное                              |

### Обязательные проверки на форме

1. **`minSupportedVersion` не может быть больше `latestVersion`.**
   Иначе будут заблокированы все пользователи, включая тех, кто установил
   самую свежую сборку — приложение станет недоступно полностью.

2. **Показать предупреждение перед сохранением, если `minSupportedVersion`
   повышается.** Например: «Пользователи версий ниже 1.2.0 не смогут
   пользоваться приложением, пока не обновятся. Продолжить?»

3. **Версия должна быть уже опубликована в сторе.** Если поднять минимальную
   версию до сборки, которая ещё проходит ревью Apple, пользователи получат
   блокировку и не найдут в сторе версию, на которую можно обновиться.

### Рекомендуемый порядок действий при релизе

1. Сборка опубликована и **реально доступна** в сторе (для iOS — прошла
   ревью, для Android — вышла из раскатки).
2. Обновить `latestVersion` → пользователи начинают видеть мягкое
   предложение обновиться.
3. Подождать несколько дней.
4. Поднимать `minSupportedVersion` **только если** старая версия действительно
   ломает работу: изменился контракт API, критический баг с ценами или
   заказами, проблема безопасности.

Обычный релиз с новыми функциями **не повод** поднимать минимальную версию.
Блокировка забирает у пользователя выбор, и применять её нужно только тогда,
когда старый клиент работает неправильно.

## Поведение приложения

### Блокировка (`minSupportedVersion` выше текущей)

Полноэкранный экран без возможности выйти: нет кнопки «назад», нет жеста
назад, нет кнопки «позже». На экране: заголовок, объяснение, текст «что
нового» (если задан), кнопка «Обновить», телефон поддержки и текущая версия
мелким шрифтом.

Телефон поддержки показан намеренно: пользователю, который по какой-то
причине не может открыть стор, нужен живой человек, а не тупик.

### Мягкое предложение (`latestVersion` выше текущей)

Нижняя шторка, показывается **не чаще одного раза за запуск** и закрывается
любым способом: кнопкой «Позже», свайпом, тапом по фону.

Навязчивое необязательное обновление приводит к тому, что пользователи
приучаются игнорировать и обязательное.

### Ошибка проверки — приложение работает как обычно

Это важно. Любая ошибка — нет сети, 404 от сервера, где endpoint ещё не
реализован, некорректный JSON — оставляет приложение в обычном режиме.

Заблокировать пользователей из-за того, что проверку **не удалось выполнить**,
было бы хуже, чем позволить им работать на версию старее. Поэтому пока
endpoint не реализован, приложение работает как раньше — ничего не сломается.

## Тестирование

1. Реализовать endpoint, вернуть `minSupportedVersion` ниже текущей версии
   приложения → приложение работает обычно.
2. Поднять `latestVersion` выше текущей → при запуске появляется нижняя
   шторка, закрывается, при следующем запуске появляется снова.
3. Поднять `minSupportedVersion` выше текущей → появляется экран-блокировка,
   кнопка «назад» и жест назад не работают.
4. Нажать «Обновить» → открывается страница приложения в сторе.
5. Выключить сеть на устройстве → приложение запускается обычно, блокировки
   нет.

Текущую версию приложения можно посмотреть в `pubspec.yaml` (поле `version`,
часть до `+`) и на самом экране блокировки внизу.

- [ ] Формат версий — `MAJOR.MINOR.PATCH`, без build number.
